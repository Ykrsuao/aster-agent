## 2026-11-10：双 Esc 清空草稿与对话回退

空闲时 600 毫秒内连续按两次 Esc：有草稿时整份清空，Ctrl+Z / Ctrl+U 可撤销；输入框为空时打开检查点列表，默认选中最新消息，也可以输入筛选。Enter 从选中消息之前创建新会话，把原始文字放回输入框，不自动发送。原会话可在 `/sessions` 中重新打开，工作文件保持当前内容。`/rewind` 提供同样入口。

单次 Esc 仍优先关闭面板和建议、撤回准备期间的待发消息或取消任务。这些操作不会成为双 Esc 的第一次按键；其他按键、粘贴、鼠标、超时及会话切换也会重置计时，按键重复和释放不会触发。存在待发队列时先处理队列。回退或加载失败保留原对话；加载期间另写草稿会保留新草稿，将选中的旧消息放入暂停队列。

后端在接收新消息前保存检查点，包含可序列化的代理状态、不可变事件版本及当时的活动事件顺序。回退后下一次模型输入不包含被舍弃的后续消息，变量、上下文和待办同步恢复；两个会话都可以在重启后打开。事件版本按内容去重，之后的压缩和删除不会改变历史检查点。旧消息没有检查点时不会列为可回退项；状态不可序列化时仍接收普通消息，但不提供不完整的回退点。回退不会恢复后台进程或已经执行的文件操作。

- 主聊天界面按 Esc 中止当前任务；如果弹窗或斜杠建议打开，Esc 先关闭该视图并保留草稿。
- 第一次 Ctrl+C 只显示退出确认，不取消任务、不清空草稿；两秒内再次 Ctrl+C 才退出。其他按键、粘贴、鼠标操作或确认超时会取消本次确认。
- 退出确认独立于任务状态，空闲、工作中和弹窗中都能显示；取消确认后仍显示原任务状态。
- 任务取消超过 20 秒仍未结束时，只提示仍在等待，保持 Cancelling 和队列暂停。TUI 不会因为这次等待自动退出或停止后端；收到请求终结响应后才恢复可用。
- 明确退出支持 Ctrl+Q 和 `/exit`，并执行有期限的后端清理。

## 2026-11-10：取消、队列与草稿（初版，取消交互已被上节调整）

本轮围绕现有终端聊天流程收尾。生产修改集中在 Rust TUI 控制器，保留现有界面和 Python 后端。

| 场景 | 原有问题 | 初版修改后行为 |
| --- | --- | --- |
| 取消运行中的任务 | 后端没有返回终结响应时一直停在 Cancelling | 最多等待 20 秒，再受控停止后端并退出；提示如何恢复已保存会话。重复取消或退出不会延长当前等待期限。 |
| 打开队列面板时自动发送队首 | 选中位置未随队列变化，Delete/Enter 可能操作另一条消息 | 保留原来选中的剩余消息，支持筛选和重复文本。 |
